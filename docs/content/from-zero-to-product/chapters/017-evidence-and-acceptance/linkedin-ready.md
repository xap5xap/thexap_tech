A browser test can pass while the question your client asked remains open.

Say a shift lead needs to find a request and leave a handoff note. In a fictional example, the unit check rejects empty notes. The integration check verifies the write. The browser script submits the note and finds it again after reopening the request. Those are three useful results.

The script already knows which request and button to pick. If the promise includes finding the right control unaided, give that action its own row. In an attended test, describe the task without naming the controls. Record what the person selected, whether anyone helped, and which build they used.

At review, keep the passing rows and mark the unaided action unobserved until you see it. This makes the next check specific and gives the decision owner a claim they can trace back to evidence.

The guide includes a worked acceptance matrix and a short review exercise.
