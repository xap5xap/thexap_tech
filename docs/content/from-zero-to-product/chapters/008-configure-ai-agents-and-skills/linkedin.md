A job title does not tell an AI agent where its job ends.

For a small task, define the result before choosing a role:

What inputs govern the work?
Which artifact should change?
What actions are allowed?
What evidence will show completion?
When should the agent stop and return a gap?

In a fictional request tracker, the job might be to propose notification-status wording. It reads the behavior contract and interface, then writes one review note. It does not edit the application, access live customer data or send a notification.

Keep the setup in distinct places: repository instructions for enduring rules, a skill for a repeated method, and a task contract for this job's exact inputs and limits. Tool access is a separate control.

Use one agent first. Add a specialist or fresh reviewer when there is a specific job for that extra handoff. A second opinion still needs evidence and someone accountable for the decision.

Try a new chat with only the contract and intended sources. Check what it actually locates and returns. A confident completion summary is not the artifact.
