A save button needs a state for “we lost the response.”

Say someone changes a title. Their connection drops after they press Save. Keep the draft visible and say “Couldn’t confirm the save.” If your API supports checking the submitted operation, give them that action. A matching acceptance can then confirm the save.

The same edit can be confirmed while a second view is still behind. In a fictional tracker, the editor confirms version 8 and the shared board still has version 7. Give the board its own freshness label until it reads version 8. An older read arriving at the editor should leave its verified version 8 in place.

Try this in one form. Drop the response, recover the exact operation, and deliver an old read last. Check the status copy, keyboard focus and what the screen reader announces. The guide includes a worked state matrix you can use to plan those checks.
