Sign-in works on your new deployment. Before you share the link, pick one thing a person came to do and follow it all the way through.

In a fictional request tracker, the test is simple. Sign in, open a seeded project, add a note, and reopen the request. If the note is still there, you have evidence about the hosted write and read path. If saving fails, keep the sign-in evidence, record the error and leave persistence open.

Write a short deployment packet before that test. Name the environment, artifact IDs, test data, cost limit and who owns cleanup. Record the browser's actual API connection, the identity callback and the expected database schema. Agree on what stops the run and which data can be discarded.

Your teammate should be able to read the packet and tell where the evidence ends. The guide walks through the test and a small recovery plan. https://www.thexap.com/blog/deploy-a-bounded-environment
