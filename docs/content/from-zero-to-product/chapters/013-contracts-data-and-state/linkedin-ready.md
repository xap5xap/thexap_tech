A green “Updated” badge can hide two different versions of the same request.

In a fictional tracker, you save a title at version 8. The shared board still has version 7. Both facts can be true, and the user needs both.

Give the accepted edit its own change ID and version. When the service commits it, show “Saved as version 8.” Track the board update separately and tie its acknowledgement to the same version. Until then, show “Board last confirmed at version 7.”

This also gives failure a place to go. A failed board update can sit beside a successful save. A late acknowledgement for version 7 cannot finish version 8. If evidence is missing, the screen can say “Board version unknown.”

Before wiring the badge, write one acceptance case for each of those moments. Name the exact record that earns the words on the screen. The guide walks through the write, read and UI contract for the same example.
