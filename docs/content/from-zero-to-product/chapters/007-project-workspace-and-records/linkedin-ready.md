Could someone open your repository without the original chat and tell what they are allowed to change?

Give them a short route to four answers:

1. The outcome the product is meant to produce.
2. The current decision governing this task.
3. The permitted changes and excluded actions.
4. The checks and evidence required for completion.

Each answer needs a canonical home. The README can be the map. Working instructions, accepted decisions, behavior specifications, and task status can live in different places without becoming competing copies.

In a fictional request tracker, the decision separates saving a request from sending its notification. An interface task follows that boundary. An older proposal to wait for email stays visible as history, with a link to the accepted decision.

Test the route with a fresh person or agent session. Ask them to cite where they found each answer and what remained unclear. A local link check helps, but it does not prove a newcomer understands the project.
